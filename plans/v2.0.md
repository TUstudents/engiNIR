# Plan: engiNIR 2.0 (collected, not decided)

Status: collected from the plans of 1.5 to 1.7 (2026-11-22). Nothing here is
decided; each item gets its decisions and its own plan before work starts.
2.0 is the release that may break the API and the project format.

## Method file and report (ICH Q14)

- A declarative, validated method file: a runner that fits, validates and
  reports from one file, and the report (HTML, maybe PDF) built on it.
- Model lifecycle (draft, validated, locked) and a write history (who changed
  which object and when).
- Model comparison (a table of models with side-by-side plots), batch fits,
  a provenance view and a command palette (`gui-1.6` "Not in 1.6").
- `Project.checks()` and `Model.verdict()` are the base the report reuses.

## Calibration transfer

- DS and PDS, and remapping a spectral axis between cameras.
- The v3 contracts reserve `band_mapping_policy` (today only `exact`) and
  `sensor_name` (not stored yet: the wavelength table's camera).
- Needs fast refits on transfer samples (the kernel engine).

## Models

- OPLS (predictive and orthogonal components from XᵀX), EPO and OSC as
  stateful recipe steps stored with the model.
- Remove NIPALS and the SVD path of PCR (the `algorithm` hyperparameter then
  has one value).
- Weighted fits (equal weight per ROI or sample): weights scale the blocks;
  per-ROI weights need per-ROI blocks (a change of the block map).
- Classification (PLS-DA), SIMCA and LDA on `gram_pca`.
- Jack-knife intervals on coefficients and VIP, the Martens uncertainty test,
  conformal or bootstrap intervals, per-object intervals (needs segmentation).

## SIMCA parity, deferred

- Component-wise cross-validation as an option, autofit rules R2, N3 and N4,
  DModXPS+, weighted DModXPS.

## Out of scope even for 2.0 unless asked

- Choosing the preprocessing automatically (needs nested cross-validation),
  CARS and genetic band searches, heteroscedastic error models, GPU or JAX
  back ends, 21 CFR Part 11 controls.
